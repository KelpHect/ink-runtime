# shaders/ — Vulkan compute kernels for the Inkling-2-Mini fp32 path

Design note: these are **correctness-first** GLSL 460 compute shaders mirroring the CPU reference (`src/model/ops.cpp`) op for op — scalar fp32 math, no cooperative-matrix/WMMA/fp8 hardware instructions, 64-thread workgroups (router uses 128 = n_experts). The mapping is deliberately one-dispatch-per-op: matvec variants per weight dtype (f32/bf16/f8e4m3 plus the two packed expert formats NVFP4 and MXFP8), convs keep their last-3 history in a device buffer the same shader optionally shifts in place, attention is split into raw scores → window+sink softmax → prob·V accumulation (the sink logit is an extra softmax column with zero V, dropped after normalization), the MoE keeps router/expert-matvec/fused SwiGLU+down-proj-accumulate as separate dispatches so a host can also fall back to the CPU reference per stage. Dequant is done in-kernel from the packed formats (E2M1 nibbles + E4M3 scales for NVFP4, E4M3 + UE8M0 powers of two for MXFP8) with fp32 accumulation throughout and the NVFP4 per-expert `amax/outer_scale_denominator` factor applied after the dot, exactly like `expert_dot`. `bindings.h` is the binding/push-constant contract; every semantic subtlety (conv tap order, selection-only router bias, raw-gate sigmoid, bf16io rounding in the message gate) is documented in each file's header comment.
